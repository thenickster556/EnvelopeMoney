# Receipt OCR (Mountain Money)

## Architecture

- **UI:** **Add** and **edit** transaction dialogs — **Camera scan** opens `ReceiptCaptureActivity` (CameraX; decode/save off the main thread); **From gallery** uses `GetContent` (`image/*`) so the photo gallery opens, not Files. Import still copies into **Pictures/Mountain Money** and persists the album URI. **Preview receipt** / **Remove receipt** use the same outlined `MaterialButton` styling as the scan row. `MainActivity` keeps a single `receiptDialogHostView` while either dialog is open so activity results route OCR to the active form.
- **List:** `item_transaction` **photo** `ImageButton` when `ReceiptRowUi.showReceiptThumbnail` is true; opens the same preview as the dialogs.
- **Preview:** `ReceiptPreviewActivity` — **fullscreen** (`Theme.EnvelopeMoney.ReceiptPreview`), sampled decode via `ReceiptBitmapLoader` (screen-based max dimension, cap 4096) from a **one-shot** byte read of the stored URI (`file://` leftover uses `FileInputStream`). Launch uses `EXTRA_IMAGE_URI` plus `content://` Intent data and `FLAG_GRANT_READ_URI_PERMISSION` so the preview activity inherits URI access; `file://` is never Intent data. Prefer `getIntent().getData()` then the extra. **Pinch-zoom**, **drag** when zoomed, **double-tap** to refit. Candidate mode also **swipes at fit-scale** (same `showCandidate` as the arrows; no wrap, no attach). A **fullscreen** toolbar button hides the top chrome and Select bar so the JPEG fills the screen; an exit overlay (or Back) restores chrome — attach still only via **Use this picture**. The pinch/pan hint is a second row of the top chrome so it cannot cover **Use this picture** (`mountain_primary` fill, white label on the always-black preview). Top chrome actions are **56dp** with **8dp** gutters (`fitCenter` glyphs) so adjacent icons are not fat-fingered. **Rotate left/right** uses **view** rotation in 90° steps until **Save rotation** (enabled when net rotation mod 360° ≠ 0); **MaterialAlertDialogBuilder** confirms **Replace / Cancel**, then `ReceiptRotatedJpegWriter.writeRotatedJpegOverwrite` decodes from the same URI, **Matrix**-rotates pixels, writes JPEG at quality **92** (`openOutputStream(uri, "w")`), and the activity **reloads** the bitmap and clears view rotation. Failed writes show a **Material** alert. **Back** / close when dirty: **Keep editing** / **Discard**. `ReceiptZoomImageView` handles gestures. If the stored pointer cannot be decoded, tap uses `ReceiptAlbumMatcher` (unique name or unique same-day leftover) then opens the repaired URI.
- **Gallery file:** Camera shots and **gallery picks** are saved upright (EXIF applied via `ReceiptExifBitmapLoader`) with `MediaStore` under **`Pictures/Mountain Money`** (`MediaStoreReceiptSaver`). `ReceiptPickerUriNormalizer` imports any non–app-owned URI **once** before OCR (`DISPLAY_NAME` / `RELATIVE_PATH` / path markers detect ownership — bare MediaStore IDs alone are not enough). `ReceiptSourceDeleter` removes the picker source when allowed (move semantics) and **never** deletes Mountain Money files. If the picker cannot be deleted, the album MediaStore URI is still persisted. **Preview** / list photo open the **stored** URI read-only (no re-import/move). A unique album filename or unique same-day leftover may repair a dead pointer after decode.
- **OCR slot:** `OcrEngine` + `PaddleOcrAdapter.createDefaultEngine()` — currently **on-device ML Kit Latin** text recognition (offline after model init). Swap in **PaddleOCR JNI** + models when packaged without changing `ReceiptFieldParser` tests.
- **Parsing:** `ReceiptFieldParser` (pure Java) + `ReceiptFieldParserTest` golden cases.
  - **Merchant (comment):** ML Kit lines sorted top-to-bottom; brand capped to **one–two words** after junk filters (phone, URL, order/points lines, survey boilerplate). ALL CAPS title-cased; comment prefilled only when empty.
  - **Total:** labeled **`$` totals** preferred bottom-up; restaurant tip composition unchanged; fallback scoring uses a 5-slot weight vector (defaults `50/80/60/25/-100`). When the user saves a different amount that appears on the OCR lines, `OcrAmountLearner` nudges those weights in sidecar SQLite.
- **Persistence:** Optional `Transaction.receiptImageUri` and backward-compatible `receiptImageFileName` (Gson) identify the saved image. Learning weights/comments are **not** Gson envelopes — see [DATA_SCHEMA.md](DATA_SCHEMA.md) sidecar.
- **Web demo:** Browser Tesseract.js produces line boxes; the JS port of `ReceiptFieldParser` prefills amount/date/merchant using the per-user learning `.db`. Images store in Mongo GridFS (`/api/receipts/:id`). Preview rotate writes JPEG 92 over the same id (temp upload, then replace; a failed rewrite restores the original id). Transfer save validates buckets **before** inserting a source row and relocates an edited transfer when the source pond changes. `GET/POST /api/learning` reads/writes that `.db`.
- **Tests:** `ReceiptRowUiTest` for list thumbnail visibility rules (placeholder row excluded).

## Protocol

Implementations follow [AI_CHANGE_PROTOCOL.md](AI_CHANGE_PROTOCOL.md): update [DATA_SCHEMA.md](DATA_SCHEMA.md), [TASK_STATE.json](../state/TASK_STATE.json), README Change Log, and run tests on a Gradle-compatible JDK.

## Recovery validation
`ReceiptAlbumMatcherTest`, `ReceiptReferenceResolverTest`, `ReceiptReferenceRepairTest` and `AndroidReceiptSourceTest` cover unique same-day unnamed repair, two same-day leftovers staying ambiguous, name beating date, reserved working files, same-day/yesterday filename references, readable metadata on failed streams, media document identifiers, exact folder queries (including `RELATIVE_PATH` without a trailing slash), unindexed files, revoked access, a partial owned-only library that must still request photo access to find other filenames, duplicate filenames, corruption, concurrent edits, shared history, restart serialization and metadata copying. Provider tests run on API 28 and 33, with a legacy permission check on API 22. `ReceiptFolderRecoveryInstrumentedTest` checks actual startup backfill, restart and preview rendering on a device/emulator.

Use a JDK compatible with Gradle 6.7.1 (validated with JDK 11). `:app:receiptRecoveryCoverage` emits HTML/XML reports; `:app:verifyReceiptRecoveryCoverage` enforces 80% line and branch coverage across the shared matcher, resolver, repair helper and Android source. Robolectric tests include Android-facing classes in JaCoCo instrumentation. See [receipt-recovery-verification.md](receipt-recovery-verification.md) for measured results and baseline limitations.
