# Receipt OCR (Mountain Money)

## Architecture

- **UI:** **Add** and **edit** transaction dialogs — **Camera scan** opens `ReceiptCaptureActivity` (CameraX; decode/save off the main thread); **From gallery** uses `GetContent` (`image/*`) so the photo gallery opens, not Files. Import still copies into **Pictures/Mountain Money** and persists the album URI. **Preview receipt** / **Remove receipt** use the same outlined `MaterialButton` styling as the scan row. `MainActivity` keeps a single `receiptDialogHostView` while either dialog is open so activity results route OCR to the active form.
- **List:** `item_transaction` **photo** `ImageButton` when `ReceiptRowUi.showReceiptThumbnail` is true; tint `?attr/colorError` when `receiptNeedsAttention` (MISSING / AMBIGUOUS / CORRUPT / PERMISSION_REQUIRED), otherwise `?attr/colorControlNormal`. TalkBack for unresolved uses `content_desc_transaction_receipt_unresolved`. Opens the same preview as the dialogs.
- **Preview:** `ReceiptPreviewActivity` — **fullscreen** (`Theme.EnvelopeMoney.ReceiptPreview`), sampled decode via `ReceiptBitmapLoader` (screen-based max dimension, cap **1600**) from a **one-shot** byte read of `content://` (`file://` uses a two-pass `decodeFile` subsample). Launch uses `EXTRA_IMAGE_URI` plus `content://` Intent data and `FLAG_GRANT_READ_URI_PERMISSION` so the preview activity inherits URI access; `file://` is never Intent data. Prefer `getIntent().getData()` then the extra. **Pinch-zoom**, **drag** when zoomed, **double-tap** to refit. Candidate mode also **swipes at fit-scale** (same `showCandidate` as the arrows; no wrap, no attach). A **fullscreen** toolbar button hides the top chrome and Select bar so the JPEG fills the screen; while that immersive candidate mode is on, a bottom translucent strip (`#66000000`) shows comment, pond, and amount (empty comment reads **No comment**). An exit overlay (or Back) restores chrome — attach still only via **Use this picture**. The pinch/pan hint is a second row of the top chrome so it cannot cover **Use this picture** (`mountain_primary` fill, white label on the always-black preview). Top chrome actions are **56dp** with **8dp** gutters (`fitCenter` glyphs) so adjacent icons are not fat-fingered. **Rotate left/right** uses **view** rotation in 90° steps until **Save rotation** (enabled when net rotation mod 360° ≠ 0); **MaterialAlertDialogBuilder** confirms **Replace / Cancel**, then `ReceiptRotatedJpegWriter.writeRotatedJpegOverwrite` decodes from the same URI, **Matrix**-rotates pixels, writes JPEG at quality **92** (`openOutputStream(uri, "w")`), and the activity **reloads** the bitmap and clears view rotation. Failed writes show a **Material** alert. **Back** / close when dirty: **Keep editing** / **Discard**. `ReceiptZoomImageView` handles gestures. If the stored pointer cannot be decoded, tap uses `ReceiptAlbumMatcher` (unique name or unique same-day leftover) then `ReceiptReferenceRepair.unusedNearby` (±1 first, then all unused album files, minus other rows) so a MISSING status still opens the in-app chooser when unused Mountain Money files exist; otherwise the repaired URI or the retry dialog.
- **Gallery file:** Camera shots and **gallery picks** are saved upright (EXIF applied via `ReceiptExifBitmapLoader`) with `MediaStore` under **`Pictures/Mountain Money`** (`MediaStoreReceiptSaver`). `ReceiptPickerUriNormalizer` imports any non–app-owned URI **once** before OCR (`DISPLAY_NAME` / `RELATIVE_PATH` / path markers detect ownership — bare MediaStore IDs alone are not enough). `ReceiptSourceDeleter` removes the picker source when allowed (move semantics) and **never** deletes Mountain Money files. If the picker cannot be deleted, the album MediaStore URI is still persisted. **Preview** / list photo open the **stored** URI read-only (no re-import/move). A unique album filename or unique same-day leftover may repair a dead pointer after decode.
- **OCR slot:** `OcrEngine` + `PaddleOcrAdapter.createDefaultEngine()` — currently **on-device ML Kit Latin** text recognition (offline after model init). Swap in **PaddleOCR JNI** + models when packaged without changing `ReceiptFieldParser` tests.
- **Parsing:** `ReceiptFieldParser` (pure Java) + `ReceiptFieldParserTest` golden cases.
  - **Merchant (comment):** ML Kit lines sorted top-to-bottom; brand capped to **one–two words** after junk filters (phone, URL, order/points lines, survey boilerplate). ALL CAPS title-cased; comment prefilled only when empty.
  - **Total:** labeled **`$` totals** preferred bottom-up; restaurant tip composition unchanged; fallback scoring uses a 5-slot weight vector (defaults `50/80/60/25/-100`). When the user saves a different amount that appears on the OCR lines, `OcrAmountLearner` nudges those weights in sidecar SQLite.
- **Persistence:** Optional `Transaction.receiptImageUri` and backward-compatible `receiptImageFileName` (Gson) identify the saved image. Learning weights/comments are **not** Gson envelopes — see [DATA_SCHEMA.md](DATA_SCHEMA.md) sidecar.
- **Web demo:** Browser Tesseract.js produces line boxes; the JS port of `ReceiptFieldParser` prefills amount/date/merchant using that user’s Mongo `learning` document. The page keeps **one** English worker and recognizes the **original** photo (the same pixels as `Tesseract.recognize`, without a 1280px JPEG re-encode). Amount and comment fill only when those fields are still empty; a found receipt date replaces the dialog date. The form stays editable while OCR runs. Default image storage is Mongo GridFS (`/api/receipts/:id`) with rotate keeping the same id (temp upload, then replace). Opt-in **Receipts on this device** writes `local://` paths through `ReceiptStorage` / `LocalFileStorage` and does not upload the JPEG. Mixed GridFS and local references resolve per transaction. Transfer save validates buckets **before** inserting a source row and relocates an edited transfer when the source pond changes. `GET/POST /api/learning` reads and writes the Mongo `learning` document (`comments` and five `weights`). Android still uses sidecar SQLite.
- **Tests:** `ReceiptRowUiTest` for list thumbnail visibility (placeholder row excluded) and `receiptNeedsAttention` (MISSING / AMBIGUOUS / CORRUPT / PERMISSION_REQUIRED vs RESOLVED / null). `ReceiptReferenceRepairTest.unusedNearby*` for the tap-path ±1 pool; `unusedNotReserved*` for leftover unused minus reserved (close-dollar append / **See all unused pictures**). `ReceiptAlbumMatcherTest` pins assigned unused photos leaving the unused pool by URI and by filename when the same JPEG later appears under another URI. `ReceiptCandidateSummaryTest` pins See all unused keeping fund amount and date. `ReceiptCandidateScorerTest` pins amount tiers (exact 100 / $2-or-10% 40 including `$20` vs `$21.66` / $5-or-25% 15 / `$29.28` vs `$21.66` miss). `ReceiptBitmapLoaderTest` pins `file://` subsample ≤ maxDim and `sampleSize` 512/64 = 16.

## Recovery validation
`ReceiptAlbumMatcherTest`, `ReceiptReferenceResolverTest`, `ReceiptReferenceRepairTest` and `AndroidReceiptSourceTest` cover unique same-day unnamed repair, two same-day leftovers staying ambiguous, name beating date, reserved working files, same-day/yesterday filename references, readable metadata on failed streams, media document identifiers, exact folder queries (including `RELATIVE_PATH` without a trailing slash), unindexed files, revoked access, a partial owned-only library that must still request photo access to find other filenames, duplicate filenames, corruption, concurrent edits, shared history, restart serialization and metadata copying. Provider tests run on API 28 and 33, with a legacy permission check on API 22. `ReceiptFolderRecoveryInstrumentedTest` checks actual startup backfill, restart and preview rendering on a device/emulator.

The same OCR pipeline that prefills new captures also **ranks recovery candidates**: while the picker is open, the ±1 shortlist and leftover unused pictures run through `ReceiptOcrPipeline`/`ReceiptFieldParser` (mode AUTO, **learned** amount weights from `currentOcrWeights()`) on `decodeSampled(..., 1280)`, and the pure `ReceiptCandidateScorer` (exact amount 100 / close $2-or-10% 40 / near $5-or-25% 15 / shared merchant tokens ≤50 / same date 20) re-sorts the rows live without rebuilding thumbs (dedicated thumb pool + LRU). Leftover unused files whose printed total is close **append** to the shortlist; **See all unused pictures (N)** (in the scroll, after the last thumb) shows every remaining unused picture with the OCR'd `$` and keeps the transaction amount and date in the dialog message. **Use this picture** on a previously unused JPEG reserves URI and filename so it does not reappear as unused, and calls `OcrAmountLearner.learn` + `saveWeights` from the stored `ReceiptDraft`. OCR never attaches anything — `Use this picture` remains the only path — and `ReceiptCandidateScorerTest` pins the arithmetic.

Use a JDK compatible with Gradle 6.7.1 (validated with JDK 11). `:app:receiptRecoveryCoverage` emits HTML/XML reports; `:app:verifyReceiptRecoveryCoverage` enforces 80% line and branch coverage across the shared matcher, resolver, repair helper and Android source. Robolectric tests include Android-facing classes in JaCoCo instrumentation. See [receipt-recovery-verification.md](receipt-recovery-verification.md) for measured results and baseline limitations.
